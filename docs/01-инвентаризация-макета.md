## 1.1. Что вернул API

| Запрос | Результат |
|---|---|
| `GET /v1/files/:key?depth=2` | 1 страница (CANVAS «Page 1»), 20 фреймов верхнего уровня |
| `GET /v1/files/:key` → `components` | **0** |
| `GET /v1/files/:key` → `componentSets` | **0** |
| `GET /v1/files/:key` → `styles` | **0** |
| `GET /v1/files/:key/styles` | **403** — токену не хватает scope `file_read`/`files:read`/`library_content:read` |
| `GET /v1/files/:key/components` | **403** — то же |
| `GET /v1/images/:key?ids=…&format=png` | 200, все 20 узлов отрисованы |

403 на `/styles` и `/components` не влияет на результат: в самом файле опубликованных стилей и компонентов **ноль**, так что эти эндпоинты вернули бы пустой список. Дизайн-система собрана из сырых узлов (`/v1/files/:key/nodes`) — см. `02-дизайн-система.md`.

## 1.3. Классификация

- **Готовые экраны — 18.** Все 20 фреймов, кроме двух оверлеев, представляют собой законченные страницы.
- **Оверлеи / попапы — 2:** `Newsletter_Popup`, `quick_view_popup`.
- **Компоненты — 0.** В файле нет ни одного компонента и ни одного набора вариантов.
- **Стайлгайд — нет.** Нет отдельного фрейма с палитрой, шкалой шрифтов, сеткой или инвентарём компонентов.
- **Черновики — нет.** Все фреймы выглядят законченными; единственный дефект — неверный заголовок «Faqs Page» на экране корзины.

Файл **не является собранным дизайн-макетом**. Признаки, полученные из данных, а не из впечатления:

|---|---|

| Из них с автолейаутом | **0** |
| Компонентов / наборов вариантов | **0 / 0** |
| Опубликованных стилей (цвет, текст, эффект) | **0** |
| Узлов со значением `cornerRadius` | **0** — все скругления нарисованы как контуры `VECTOR` |
| Типы узлов | `GROUP` 1747, `VECTOR` 1721, `TEXT` 1539, `RECTANGLE` 263, `FRAME` 14 |
| Гарнитур в тексте | **19** |
| Размеров кегля | 44 разных значения, в том числе дробные: 11.228, 12.363, 15.539, 19.99, 45.959 |

Дробные кегли, отсутствие автолейаута, отсутствие скруглений как свойства и 1721 векторный контур — это следы **автоматической трассировки готового HTML-шаблона** (Organi — существующий коммерческий Bootstrap-шаблон), а не ручной сборки в Figma.

**Что из этого следует практически:**

1. Переиспользовать компоненты Organi нельзя — их нет. Любой «новый экран из компонентов Organi» придётся сначала эти компоненты создать.
2. Значения токенов приходится **измерять и нормализовать**, а не считывать. Шесть оттенков зелёного (`#81C408`, `#7CC000`, `#7FBA00`, `#82C408`, `#9FCB22`, `#62A403`) — это не палитра из шести ролей, а погрешность трассировки одного-двух цветов.
3. Правки в Figma по этому файлу дороги: нет автолейаута — каждый сдвиг двигается руками.
4. Это напрямую влияет на выбор формата производства — см. `05-отчёт-и-рекомендация.md`.
