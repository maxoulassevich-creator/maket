# Этап 6. Производство: что сделано, как устроено, что дальше

Формат согласован Заказчиком: **(в) комбинация** — HTML/CSS-прототип на извлечённой
дизайн-системе плюс аннотации Что / Как / Зачем внутри него же.
Тема WordPress **не делается**: на выходе обычные статичные HTML-страницы,
общий CSS и общий JS. Экраны административной части в объём **не входят**
(админка собирается стандартными средствами WordPress).

```
    pages/                  тела страниц + блок meta

    decor.css               декоративный слой

    prototype.js            переключатель роли, аннотации, поведение интерфейса
    decor/                  12 декоративных ассетов из исходного макета
    products/               45 изображений товаров в веб-размере
```

### Зачем сборщик, если нужны обычные HTML-страницы

Шапка и подвал одинаковы на 35 страницах. Держать 35 копий руками нельзя —
они разъедутся на второй правке. Партиалы лежат один раз в `_src/partials`,
`python3 build.py` собирает из них **самостоятельные `.html`-файлы**,
которые открываются двойным кликом и ничего не требуют: ни сервера, ни интернета.

Синтаксис шаблонов — четыре конструкции, описаны в шапке `build.py`.

---

## 6.2. Главное решение: роль переключает разметку, а не стили

ТЗ 4.1: *«скрытие кнопок только средствами CSS не допускается»*.
«Структура»: *«это не "спрятать стилями" — этих элементов просто нет на публичных экранах»*.

Реализовано так: содержимое для чужой роли лежит внутри `<template>`, а браузер
содержимое `template` в DOM **не помещает вообще**. `prototype.js` разворачивает
только подходящий роли блок, остальные удаляет.

```html
<template data-role-only="wholesale">…корзина…</template>
<a href="wholesale.html" data-role-hide="wholesale">Оптовым покупателям</a>
```

- `data-role-only="guest applicant"` на `<template>` — содержимое попадает в DOM
  только для перечисленных ролей;
- `data-role-hide="wholesale"` на обычном узле — узел **удаляется**, не прячется.

Переключение роли перезагружает страницу — как серверный рендеринг.

**Проверено автоматически:** у гостя и заявителя 0 кнопок покупки и нет узла
`.mini-cart`; у оптовика — 4–8 кнопок и корзина с суммой.

и обрезаны по содержимому — 15,4 МБ. Оригиналы остались в `assets/products/`
в корне репозитория.

## 6.4. Что проверяется автоматически

Скрипт снимает страницу в трёх ролях и на 430 px, и проверяет:

| Проверка | Требование |
|---|---|
| Горизонтальный скролл | ТЗ 23.2 — его не должно быть |
| Кнопки покупки у гостя и заявителя | ТЗ 4.1, 25.2 — их должно быть 0 |
| Неразвёрнутые `<template>` | Не должно остаться |
| Цена без единицы измерения | «Структура» — единица обязательна всегда |
| Битые изображения | — |
| Числа в таблицах не моноширинные | «Структура», «Таблицы и статусы» |
| Ошибки JS | — |

Все шесть собранных страниц проходят проверку во всех проверенных ролях
и на мобильной ширине.

## 6.5. Соглашения, которые нужно соблюдать дальше

1. **Никаких новых цветов, кеглей и отступов.** Только переменные из
   `design-system.css`. Если значения не хватает — сначала обосновать
   по `docs/02-дизайн-система.md`.
2. **Цена всегда с единицей.** Разметка: `.price` + `.price__value` +
   `.price__unit`. Без `.price__unit` автопроверка падает.
3. **Числа в таблицах** — класс `.num` на `td`/`th`: правый край + моноширинные.
4. **Статус — цвет плюс подпись.** Класс `.status` рисует точку и текст;
   точка без текста не допускается.
5. **Незаполненных данных не показываем.** Ни прочерка, ни заглушки —
   строка или секция не выводится вовсе. Данные, которые предоставляет
   Заказчик, помечены `[в квадратных скобках]`.
6. **Придуманных данных нет** (ТЗ 7.5). Цены, остатки, сроки и производители
   в прототипе — демонстрационные и подписаны как таковые в аннотациях;
   реквизиты, адрес, телефон и юридические тексты оставлены пустыми.
7. **Таблицы на телефоне** — класс `.table--cards` плюс `data-label` на каждой
   ячейке, иначе строки не перестроятся в карточки.
8. **Каждая секция получает аннотацию** — `<script class="ann" type="application/json">`
   с полями `section`, `what`, `how`, `why`, `src`. Это и есть согласованная
   текстовая спецификация: она живёт внутри прототипа, а не отдельным файлом.

## 6.6. Что осталось

**Собрано 6 страниц из 35.** Полный список с приоритетами — `docs/04-пробелы.md`, п. 4.4.

Порядок, в котором имеет смысл продолжать:

1. **`styleguide.html`** — палитра, шкала, сетка и все ~25 компонентов
   в 37 состояниях на одном экране. Без него остальное несопровождаемо:
   это та библиотека компонентов, которой в Figma нет.
2. **Оптовый контур** — `wholesale`, `wholesale-register`, `wholesale-status`,
   `login`, `cart`, `checkout`, `checkout-received`. Здесь сосредоточены
   почти все требования, которых Organi не покрывает: формы с ошибками,
   две цены в строке, предупреждение об изменении цены, размер предоплаты,
   плашка «онлайн-оплаты нет».
3. **Личный кабинет** — 8 страниц, донора нет ни у одной.
4. **Остальная публичная витрина** — акции, новинки, подарки, поиск, журнал,
   о гастромаркете, второй этаж, контакты, юридические.
5. **Состояния и пустые экраны** — 404 в двух сценариях, служебное сообщение
   в пяти, пустая корзина, пустой поиск, пустая категория, нет заказов.

Вопросы Заказчику, оставшиеся открытыми (№3–№10), — в `docs/05-отчёт-и-рекомендация.md`, п. 8.
Ответы получены только на №1 (формат — комбинация) и №2 (админка — не входит).
